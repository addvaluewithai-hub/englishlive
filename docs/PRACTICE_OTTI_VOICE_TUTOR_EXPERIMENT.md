# Otti-led Practice: voiced briefing, silent Live error notebook, voiced debrief

**Experimental Draft PR. 2026-10-14.** Supersedes the failed Flash-Lite post-session recording experiment (PR #44).

## Three learner phases

1. **Before:** Mission screen is compact (goal and authored scenario facts). The learner clicks **Listen to Otti**, a deliberate audio gesture. Otti uses `gemini-3.8-live` audio to give a short introduction and **speak the authored canonical sample dialogue**, marking Partner and Learner roles. This demonstration is not assessed and sends **no microphone audio**. The learner can skip it or replay it.
2. **During:** Otti stays a natural roleplay character on the existing Live audio runtime. Practice opts out of the unreliable provider `inputAudioTranscription`. Two optional `NON_BLOCKING` Live tools return `SILENT` acknowledgements: `record_language_issue` saves high-confidence heard mistakes, and `record_practice_progress` marks **authored speaking goals clearly demonstrated by the learner**. The original goal-pill/checklist UI has been restored on the Live screen and recap. It supports multiple goals in one answer and out-of-order moves. **These observations never gate Otti's questions, require retries or imply mastery.** There is no Flash-Lite, WAV buffer or automatic Background Coach assessment.
3. **After:** The user finishes and the in-memory issue notebook is passed to the review route. The learner clicks **Listen to Otti** to hear a brief voice explanation generated by **the same Gemini Live Otti persona**, constrained to the recorded issues. The page **also prints a written report** with original heard phrase, suggested better English and explanation. No text-only independent coach is invoked.

## Why not a transcript?

Gemini Live can interpret intent while provider input transcription is inaccurate. The new notebook records **only optional, high-confidence language issues Otti believes it clearly heard**, not a full verbatim transcript. It is not proven ground truth or a proficiency score; a zero-issues session means no issues were recorded, not flawless speech. This experiment intentionally does **not** attempt to reconstruct every utterance.

## Privacy and implementation

- No extra microphone recording, WAV uploads or separate STT service. Voice still streams to Gemini Live as it did before; Live tool calls and debrief contain **textual evidence** in browser memory for the route transition. No new app database writes.
- Model-issued tool args are **untrusted**. The collector rejects missing text, same original/better, non-high confidence, duplicates and excessive issues (maximum 12). This cannot prove the words were actually spoken; the system instruction requires high confidence and says to abstain if uncertain.
- Voice briefing and debrief open **independent audio-only Live narration sessions** on direct user gesture; no microphone permissions. They are optional with visible fallback when unavailable.
- The optional **Hint** button may still use an existing HTTP hint generator when explicitly requested; it does **not** act as a reviewer. The prior `/api/practice/coach` route remains in code for compatibility, but automatic background reviews and final recap requests are disabled for these missions.
- Checkmarks on the restored mission checklist mean Otti observed a learner communication move, **not** a score, mastery claim, or guaranteed verbatim evidence. The tool whitelists this mission's required beat IDs; foreign goals and ending beats cannot receive ticks.

## Acceptance tests before merging

- CI: `npm run check`, `npm run test:ui`, `npm run test:practice` and visual QA.
- Check all A2 goal pills (drink, size, hot/cold, add-ons) remain visible while speaking and in recap. Test a combined learner answer; Otti may tick multiple goals in any order without repeating answered questions or waiting on tools. A question asked by Otti alone must NOT tick a goal.
- Authenticated real-microphone A2 scenario: short answers, grammatically incorrect answers, clean utterances, repeats, silence, mid-sentence pauses and interruption. Confirm the conversation stays fluent; verify the tool is invoked on real audible issues, doesn't interrupt, and does **not** invent originals.
- Exercise introductory voice: Arabic description + English model dialogue, same Otti voice, no mic prompt. Model narration is *guided*, not deterministic prerecorded speech; listen for deviation and add fixed audio if exact sample reading is required.
- Exercise final voice: each recorded correction read correctly; never invent a new mistake; zero issues gets cautious messaging.
- Test navigation/cancel, model outages, double play and replay, and browser audio gesture on iOS/Android.
- Check privacy policy and consent language regarding extra **textual** learning notes; no new audio recording is added.

**Do not merge until signed-in real voice QA confirms Gemini 3.8 Live tool behavior and spoken narration in the selected deployment.**
